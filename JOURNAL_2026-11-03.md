## Steps

1. **Check that no final went in already.**
   - Look for a `final_submission` operation in `starter-kit/.icaif/checkpoint.json`, and
     check the website's My Submissions.
   - If one exists, stop and tell the owner.
2. **Make a private template**, outside git (for example `output/final/template/`). Copy
   `starter-kit/examples/final/final_submission.json` and set:
   - `materials_url` and `materials` as above;
   - `team_members`: every registered member exactly as in `register.json` (name, email,
     institution). The emails must match their Codabench accounts.
   - Leave `team_id` and `team_token` as placeholders.

   The kit's format check passed on such a template on the personal laptop
   (`validate_submission.py --allow-placeholders`).
3. **Fill the credentials and validate**, from `starter-kit/`:
   ```bash
   python tools/prepare_submission.py ../output/final/template/final_submission.json --output ../output/final/final_submission.json
   python tools/validate_submission.py ../output/final/final_submission.json
   ```
   - `prepare_submission.py` takes `TEAM_ID` and `TEAM_TOKEN` from the environment or
     `starter-kit/.env`, and never overwrites an existing output.
   - The output carries the team token: keep it private (`chmod 600`), and never commit
     or print it.
4. **Show the owner the validated file with `team_token` redacted.** Do not upload. The
   owner uploads it on the website's My Submissions page (or approves
   `python tools/auto_submit.py final --file …` from `starter-kit/`).
5. **Record the receipt.** Add a journal entry with the submission id and status.
   - `PENDING_SELECTION` is normal at first, then `PENDING_REVIEW`.
   - Never resubmit while pending.
   - No folder link, emails or token go in the journal.
